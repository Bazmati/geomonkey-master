# Encaisser une cotisation hors-ligne

## Besoin
Le bureau encaisse parfois des cotisations en main propre (espèces à l'AG,
chèque, virement) sans passer par Stripe. Aucune trace n'existait dans l'app :
il fallait créer l'adhésion « à la main » en base.

## Fonctionnement
Bouton « Encaisser hors-ligne » sur /admin/membership/list → page
/admin/membership/hors-ligne (accès bureau : voter ENTITY_EDIT, comme le
reste du module adhésions).

Formulaire : membre (tous les comptes), montant encaissé en € (défaut : le
tarif courant), moyen de paiement (espèces / chèque / virement).

À la validation, l'action réplique la logique post-paiement du webhook
Stripe (createOrUpdateMembership) :
- désactive les adhésions existantes du membre
- crée une Membership paid, active, valable 1 an (startedAt/expiresAt)
- trace le paiement dans stripe_payment_id : « MANUEL-<moyen>-<Ymd-His> »
  (pas de migration de schéma, la colonne existait)
- passe le simple visiteur en membre_actif (OfficeFunction::None → ActiveMember)
- confirme l'inscription (isRegistrationConfirmed, registrationValidatedAt)
- met à jour membershipValidUntil (paiement + 1 an)
- envoie le mail M4 de confirmation (non bloquant comme dans le webhook)

Pas de doublon Stripe : aucun appel à l'API, aucune session de paiement.

## Tests
php bin/phpunit tests/Controller/Admin/MembershipOfflinePaymentTest.php
Le trésorier peut repérer les encaissements manuels dans la liste :
badge « hors-ligne » à côté de « payée ».

## Déploiement (rituel habituel)
1. Extraire à la racine du projet.
2. php bin/phpunit
3. git add/commit/push
4. CT 202 : git pull + cache:clear --env=prod + reload php8.4-fpm
5. Vérifier en prod : bouton sur /admin/membership/list, encaissement d'un
   test en prod avec un vrai membre du bureau puis vérifier la liste et le
   mail M4 reçus.
